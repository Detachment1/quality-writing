# OpenWiki 指令（示例：生成高质量术语表）

> 用法：把本文件内容复制到你的仓库 `<repo>/openwiki/INSTRUCTIONS.md`，再运行 `openwiki --update --language zh-CN`。
> 注意：`openwiki/INSTRUCTIONS.md` 是用户自写的 brief，`--init` / `--update` 不会覆盖它。

## 语言与读者
- 用中文生成（运行时加 `--language zh-CN`）。
- 读者是 coding agent 与开发者。开发者读者模型：有基础代码知识 + 前序需求知识，但无本仓库新模块的先验知识。
- 遵循《统一写作方法论》：先总览后细节、零跳跃、从简到繁、言简意赅。

## 必须生成的页面（优先级从高到低）
1. `术语表.md` —— 最高优先级，规范见下。
2. 架构、模块、接口、数据表/字段等常规页面。

## 术语表规范（核心）
- 表格固定为六列：`| 中文术语 | English | 代码真实命名 | 定义 | 别名/禁用词 | 出处(证据) |`
- 每个术语必须满足：
  - 来自代码真实命名（类名/接口名/表名/字段名），并在「出处」列给出 repo 证据（`repo://` 路径）。
  - 一词一义：同一概念全文只用一个词；「别名/禁用词」列列出该概念的其他叫法和禁止使用的词。
  - 定义一句话，站在无先验知识读者的角度写清楚。
- 按领域分组（如：领域模型 / 接口 / 数据表 / 配置项）。
- 代码里不存在、且团队尚未约定的术语，禁止凭空创造；必须提及时标 `[待定]`。

## 优先级与跳过
- 优先：公共 API、数据模型、核心领域概念、跨模块术语。
- 跳过：生成物、测试桩、内部工具脚本细节（除非其命名被业务代码引用）。
