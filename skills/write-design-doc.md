# 写软件设计文档（场景技能）

> 本技能是「薄适配」：只定义场景特有信息，**质量规则一律引用《统一写作方法论》**，不在此重复。

## 引用（先读，再执行）

- 方法论：`methodology/writing-methodology.md`（唯一权威，严格按其原则执行）
- 术语源：代码仓 openwiki（模块/类/接口/表/字段真实命名）+ `glossary/` 术语表

## 场景特有信息

- **读者模型**：有基础代码知识 + 前序需求知识，但**没有本次新需求任何先验知识**的开发者（与方法论一致）。
- **用途**：设计评审、指导开发。
- **总览层形态**：架构图/流程图 + 改动点列表。
- **展开顺序**：图 → 改动点 → 逐点细节。

## 章节骨架

1. 背景与目标
2. 总览：架构图/流程图 → 改动点列表（明确要动哪些地方）
3. 逐点细节：每个改动点分别展开（逻辑/接口/数据/影响面）
4. 风险与验证

## 执行流程（严格按方法论）

1. **拆解**：先输出脑图骨架（短标签、MECE 分类、复杂逻辑/算法单独标注），**等用户确认后再展开**。
2. **展开**：按确认骨架 + 读者模型，用「图 → 改动点 → 逐点细节」展开。
3. **验收**：用方法论「阶段二通用四问」自检，逐条修复跳跃/脑补点，再交付。

## 术语铁律

所有模块名/接口名/表名/字段名必须取自代码仓 openwiki 的真实命名；不确定的标 `[待定]`，绝不自造。
