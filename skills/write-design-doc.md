# 写软件设计文档（场景技能）

> 薄适配：只填场景特有信息，质量规则一律引用《统一写作方法论》，不在此重复。

## 引用（必须在开头，先读再执行）

- 方法论：`methodology/writing-methodology.md`（唯一权威）
- 术语源：openwiki 术语表（代码仓「模块/类/接口/表/字段」真实命名）

## ① 读者与用途

读者：有基础代码知识 + 前序需求知识，但无本次新需求任何先验知识的开发者。
用途：设计评审、指导开发。

## ② 总览层形态 + 章节骨架

总览层：架构图/流程图 + 改动点列表。
展开顺序：图 → 改动点 → 逐点细节。
章节骨架：
1. 背景与目标
2. 总览：架构图/流程图 → 改动点列表（明确要动哪些地方）
3. 逐点细节：每个改动点分别展开（逻辑/接口/数据/影响面）
4. 风险与验证

## ③ 术语域

所有模块名/接口名/表名/字段名必须取自 openwiki 术语表（代码仓真实命名）；不确定的标 `[待定]`，绝不自造。
